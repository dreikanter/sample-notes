# CSS container queries — notes after finally using them

Container queries landed in all major browsers in late 2022 and I finally had a real use case for them in a project this week. Quick notes while it's fresh.

**The problem they solve**

Media queries respond to viewport size. Container queries respond to the size of a containing element. This matters for components: a card component might live in a 400px sidebar column on desktop and full-width on mobile — you want the card to respond to its context, not to the viewport.

**Basic syntax**

```css
.card-container {
  container-type: inline-size;
  container-name: card;
}

@container card (min-width: 600px) {
  .card {
    display: grid;
    grid-template-columns: 200px 1fr;
  }
}
```

`container-type: inline-size` makes the element a containment context for inline dimension queries. You can also use `size` for both axes, but `inline-size` is more common and has better performance characteristics.

**Gotcha: querying the container itself**

You can't query a container and style the container in the same rule. Style the children. This is by design — it would create a feedback loop.

**cqw / cqh units**

These are relative to the container dimensions, analogous to `vw`/`vh`:

```css
@container (min-width: 400px) {
  .card-title { font-size: 5cqw; }
}
```

**Browser support**

Baseline 2023 — all major engines. Safe to use without fallbacks for non-critical enhancements.
