# Docker compose — reference for local development setup

Notes on the compose setup I've been refining for the current project. Full compose spec reference: https://docs.docker.com/compose/compose-file/

## Basic structure

```yaml
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile.dev
    ports:
      - "3000:3000"
    volumes:
      - .:/app
      - /app/node_modules
    environment:
      - NODE_ENV=development
      - DATABASE_URL=postgres://user:pass@db:5432/mydb
    depends_on:
      db:
        condition: service_healthy

  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass
      POSTGRES_DB: mydb
    volumes:
      - db_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U user -d mydb"]
      interval: 5s
      timeout: 5s
      retries: 5

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"

volumes:
  db_data:
```

## Volume mount pattern

The double volume mount for Node:
```yaml
volumes:
  - .:/app
  - /app/node_modules
```

The second entry prevents the container's `node_modules` from being overwritten by the empty host directory. Learned this the hard way.

## Useful commands

```bash
docker compose up --build         # rebuild images
docker compose exec app bash      # shell into running container
docker compose logs -f app        # follow logs for one service
docker compose down -v            # destroy containers AND volumes
```

## Profiles for optional services

```yaml
services:
  mailhog:
    image: mailhog/mailhog
    profiles: ["mail"]
```

Start only when needed: `docker compose --profile mail up`
