# Git worktrees — quick reference

Worktrees let you check out multiple branches simultaneously into different directories. Extremely useful when you need to hotfix main while mid-feature on a branch.

**Create a worktree**

```bash
git worktree add ../project-hotfix main
git worktree add ../project-feature feature/new-nav
```

**List worktrees**

```bash
git worktree list
```

**Remove a worktree**

```bash
git worktree remove ../project-hotfix
# Or if the directory is already gone:
git worktree prune
```

**Things to know**

- Each worktree shares the same `.git` directory but has its own working tree and index.
- You cannot check out the same branch in two worktrees at once — git will refuse.
- Branches created in one worktree are immediately visible from all others.
- Hooks run relative to the worktree's working directory, not the main repo root — check your hook paths.
- Lock a worktree so `prune` won't delete it accidentally: `git worktree lock ../project-hotfix`.

**When I use this**

Mainly for: reviewing a colleague's PR without stashing my current work, running tests on main alongside a feature branch to compare outputs, and keeping a "scratchpad" worktree for quick experiments.

Full docs: [git-scm.com/docs/git-worktree](https://git-scm.com/docs/git-worktree)
