# HTTP caching headers — practical reference

This keeps tripping me up. Writing it down properly.

Reference: https://developer.mozilla.org/en-US/docs/Web/HTTP/Caching

## Cache-Control directives

**For responses (server → client):**

```
Cache-Control: max-age=3600
```
Cache for 1 hour. After that, the browser must revalidate.

```
Cache-Control: no-cache
```
Misleading name — doesn't mean "don't cache." It means "cache it but revalidate before using." The browser stores it but checks with the server before serving from cache.

```
Cache-Control: no-store
```
Don't cache at all. Use for sensitive data (auth pages, etc.).

```
Cache-Control: private
```
Only the browser can cache it; intermediate proxies/CDNs cannot.

```
Cache-Control: public, max-age=86400, stale-while-revalidate=3600
```
Cache publicly for 24h. For 1 hour after expiry, serve stale while revalidating in the background. Good for static assets with real-time requirements.

## ETag and conditional requests

Server sends:
```
ETag: "abc123"
```

Browser stores the ETag. On next request:
```
If-None-Match: "abc123"
```

If resource unchanged, server responds 304 Not Modified (no body). Fast and bandwidth-efficient.

## Immutable assets

```
Cache-Control: public, max-age=31536000, immutable
```

One year. The `immutable` hint tells browsers not to revalidate even on hard reload. Use only with content-hashed asset URLs (e.g., `main.a3f2c9.js`).

## Practical pattern for a Next.js app

- HTML pages: `no-cache` (check every time, serve fast if unchanged)
- API responses: depends on data freshness requirements
- Static assets: `max-age=31536000, immutable` with fingerprinted URLs
