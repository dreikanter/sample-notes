# Prometheus and Grafana — quick setup notes

Set up a basic monitoring stack for the dev environment this week. Notes for reproducibility.

Reference: https://prometheus.io/docs/introduction/overview/

## Architecture

Prometheus scrapes metrics from targets on a configurable interval. Targets expose a `/metrics` endpoint in the Prometheus exposition format. Grafana queries Prometheus and builds dashboards.

## Docker Compose setup

```yaml
services:
  prometheus:
    image: prom/prometheus:latest
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    ports:
      - "9090:9090"

  grafana:
    image: grafana/grafana:latest
    ports:
      - "3001:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin
    depends_on:
      - prometheus
```

## prometheus.yml

```yaml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: 'app'
    static_configs:
      - targets: ['app:3000']
    metrics_path: '/metrics'
```

## Exposing metrics from Node.js

Using the `prom-client` library:

```javascript
const client = require('prom-client');
const register = new client.Registry();
client.collectDefaultMetrics({ register });

// Custom counter
const httpRequests = new client.Counter({
  name: 'http_requests_total',
  help: 'Total HTTP requests',
  labelNames: ['method', 'status', 'route'],
  registers: [register],
});

app.get('/metrics', async (req, res) => {
  res.set('Content-Type', register.contentType);
  res.end(await register.metrics());
});
```

## Useful default metrics

`process_cpu_seconds_total`, `process_resident_memory_bytes`, `nodejs_eventloop_lag_seconds` are collected by `collectDefaultMetrics` and cover most basic health questions.
