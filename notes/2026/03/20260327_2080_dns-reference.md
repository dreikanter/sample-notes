# DNS reference

A quick reference for DNS record types and troubleshooting commands. I look these up less often than I should remember them.

## Record types

| Type  | Purpose | Example |
|-------|---------|---------|
| A     | IPv4 address | `example.com → 93.184.216.34` |
| AAAA  | IPv6 address | `example.com → 2606:2800::1` |
| CNAME | Alias to another name | `www → example.com` |
| MX    | Mail server | `10 mail.example.com` (priority number) |
| TXT   | Text data | SPF, DKIM, domain verification |
| NS    | Nameservers for zone | `ns1.example.com` |
| SOA   | Start of authority | Zone metadata |
| SRV   | Service location | `_http._tcp` records |

## Lookup commands

```bash
# Basic lookup
dig example.com           # A record
dig example.com MX        # MX records
dig example.com ANY       # all records (not all resolvers support)

# Specify nameserver
dig @8.8.8.8 example.com  # query Google's resolver directly

# Reverse lookup (PTR)
dig -x 93.184.216.34

# Short output
dig +short example.com

# Trace the delegation path
dig +trace example.com
```

`nslookup` is older but simpler for quick checks:
```bash
nslookup example.com
nslookup -type=MX example.com
```

## TTL

Time to Live: how long a record is cached. Low TTL (60s) means changes propagate quickly but generate more queries. High TTL (86400 = 1 day) is efficient but means changes take longer to propagate.

## Common issues

**CNAME at apex**: Don't put a CNAME on the root domain (`@`). It breaks MX and NS records. Use an ALIAS/ANAME record (some providers) or A record instead.

**SPF alignment**: Make sure your SPF record includes all services sending email on your behalf.
