# CRDT basics – first understanding

From the [[20251231_2025]] backlog: "Understand CRDT basics well enough to explain them to someone else." Working through this now.

**CRDT** = Conflict-free Replicated Data Type. A data structure designed so that concurrent updates on different nodes can always be merged without conflict.

## The problem they solve

In distributed systems, the same data can be modified on multiple nodes simultaneously (no network, or intentional offline use). When the nodes reconnect, you need to merge these divergent states. Naive approaches produce conflicts that require human resolution (git merge conflicts, for example). CRDTs are designed so that merging is always deterministic and produces the same result regardless of order.

## Two main categories

**State-based (CvRDTs)**: each node periodically sends its full state. Merge is done by taking the "join" of two states. Requires a join function that is commutative, associative, and idempotent.

**Operation-based (CmRDTs)**: nodes broadcast operations rather than state. Requires causal delivery (operations received in causal order) but can be more efficient than shipping full state.

## Simple examples

**G-Counter (grow-only counter)**: Each node has a slot in a vector. Increment only ever touches your slot. Merge takes element-wise max. Value is the sum of all slots. Always consistent because you can never "undo" an increment.

**2P-Set**: Two G-Sets — one for additions, one for removals. An element is in the set if it's in the add set but not the remove set. You can only remove what's been added. Tricky edge case: once removed, can't re-add.

More sophisticated: OR-Set (Observed-Remove Set) solves the re-add problem with unique tags.

## Where they're used

Figma's multiplayer editing, Notion collaborative editing, Apple's Notes sync, Redis Cluster.
