# Sprint retrospective notes — 7 Nov

Format: Start / Stop / Continue. Ran for 45 minutes, 8 people, remote.

## Start

- Writing better ticket descriptions before sprint start — several tickets this sprint required significant clarification mid-sprint, which broke flow
- Using async Loom videos for knowledge sharing instead of always defaulting to synchronous meetings — experiment proposed by team member, team agreed to try it
- Dedicated "tech debt Friday" blocks (even two hours) — came up for the third sprint in a row, probably time to actually schedule it

## Stop

- Adding tickets to the sprint after it starts without explicit agreement — happened twice, caused scope creep
- Long standups — currently averaging 25 minutes, target should be 10–12. Proposal to use a written async format for basic updates and only sync when there's genuine blockers

## Continue

- Pair programming on complex tickets — the auth middleware work done in pairs was significantly better quality than the solo work
- Clear definition of done including QA sign-off
- Slack thread for sharing interesting articles and learning — lightweight but genuinely valued by team

## Action items

1. Product lead to write a ticket template by end of week
2. Try async standups for one sprint using a Slack bot (looking at [Geekbot](https://geekbot.com) as an option)
3. Schedule four 2-hour tech debt blocks distributed through next sprint

## My own notes

The async standup idea might actually be an improvement. The synchronous standup has become performative — people are reporting to the meeting rather than to each other. Worth trying.
