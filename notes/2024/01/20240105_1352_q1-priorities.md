# Q1 2024 engineering priorities

Draft for team conversation. Keeping this short intentionally.

## The one real bet

**Read replica for reporting.** The indexes bought time (see [[20231123_1321]]) but the fundamental problem is that reporting queries compete with write traffic on the primary. Moving the reporting layer to a read replica removes the contention and gives us room to grow without careful index management.

This is not a quick project: it requires auditing which queries can go to the replica, handling replication lag for time-sensitive reads, and updating the ORM configuration. Estimate: 3–4 sprints.

## Supporting work

- Alert audit and cleanup (overdue, will block on this)
- Auth service upgrade — the current version has a known CVE that's low severity but should be closed
- Performance baseline — we don't have a consistent way to measure improvement, which means we can't tell if the work is working

## What we're explicitly not doing

- Microservices decomposition (still not necessary at this scale)
- GraphQL layer (no evidence the REST API is a bottleneck)
- Major frontend work (agreed to defer until Q2 with the product team)

## Risks

1. The read replica work is estimated loosely and could expand if replication lag handling is more complex than expected
2. Q1 has fewer working days than nominal due to holidays in January and a team offsite in February
