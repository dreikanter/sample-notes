# Python dataclasses — practical notes

Dataclasses landed in Python 3.7 and I still see codebases using namedtuples or plain dicts where a dataclass would be clearer. Notes on the practical cases.

**Basic usage**

```python
from dataclasses import dataclass, field
from typing import List

@dataclass
class Task:
    title: str
    priority: int = 3
    tags: List[str] = field(default_factory=list)
```

The `field(default_factory=list)` pattern is important — using `tags: List[str] = []` is a bug because mutable defaults are shared across instances.

**Frozen dataclasses**

```python
@dataclass(frozen=True)
class Point:
    x: float
    y: float
```

Frozen instances are immutable and hashable, so they can be used as dict keys or in sets. Good for value objects.

**Post-init processing**

```python
@dataclass
class Circle:
    radius: float
    area: float = field(init=False)

    def __post_init__(self):
        self.area = 3.14159 * self.radius ** 2
```

`__post_init__` runs after `__init__`. Use it for derived fields or validation.

**Comparison**

By default, dataclasses generate `__eq__` based on all fields. Add `order=True` to also get `<`, `>`, etc., using field order.

**When not to use them**

When you need custom `__init__` logic that's too complex for `__post_init__`, or when you need full ORM-style behavior, a regular class or attrs/pydantic is better.
