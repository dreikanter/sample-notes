# PostgreSQL window functions cheatsheet

Window functions operate across rows related to the current row without collapsing the result set like GROUP BY would. Extremely useful for rankings, running totals, and lag/lead comparisons.

**Basic syntax**

```sql
SELECT
  col,
  func() OVER (PARTITION BY group_col ORDER BY sort_col)
FROM table;
```

**ROW_NUMBER, RANK, DENSE_RANK**

```sql
-- Rank orders within each category
SELECT name, category, sales,
  RANK() OVER (PARTITION BY category ORDER BY sales DESC) AS rank
FROM orders;
```

RANK() skips numbers after ties (1, 2, 2, 4). DENSE_RANK() does not (1, 2, 2, 3). ROW_NUMBER() always gives a unique number regardless of ties.

**Running total**

```sql
SELECT date, amount,
  SUM(amount) OVER (ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM transactions;
```

**LAG and LEAD**

```sql
SELECT date, revenue,
  LAG(revenue, 1) OVER (ORDER BY date) AS prev_day,
  revenue - LAG(revenue, 1) OVER (ORDER BY date) AS day_change
FROM daily_metrics;
```

**NTILE** — divide rows into N equal buckets:

```sql
SELECT customer_id, spend,
  NTILE(4) OVER (ORDER BY spend DESC) AS quartile
FROM customers;
```

Full docs: https://www.postgresql.org/docs/current/tutorial-window.html

The ROWS vs RANGE distinction in frame clauses trips people up. ROWS is physical rows; RANGE uses the ORDER BY values and can include ties. ROWS is usually what you want for running totals.
