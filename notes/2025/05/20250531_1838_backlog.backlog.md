# Learning backlog — programming topics

Items I want to study or build at some point. Rough priority order but subject to change.

## High priority

- **WebAssembly fundamentals** — understand the compilation model, memory model, and JS interop. Not to become a Wasm developer but to stop being confused when it comes up. Good starting point: https://developer.mozilla.org/en-US/docs/WebAssembly
- **Distributed tracing** — set up OpenTelemetry in a test project, understand how spans and traces relate, connect to Jaeger or similar. The theory makes sense but I haven't built anything with it.
- **SQLite for server-side use cases** — a lot of the "you don't need Postgres" discourse is interesting. Understand the concurrency limits and when SQLite legitimately handles production loads.

## Medium priority

- Rust — specifically the ownership model. Have started and stopped twice. The right entry point might be a small CLI tool rather than working through the book linearly.
- CSS container queries — these are now well-supported and I keep reaching for media queries out of habit.
- Temporal API — the replacement for JavaScript Date. It's in stage 3, has a polyfill, worth learning before it ships widely.

## Low priority / nice to have

- Typst — document layout system that might replace LaTeX for some use cases
- Nix — reproducible builds, everyone seems to love it, I remain baffled
- Prolog — purely for the mental model shift, not for building things

Review this list monthly. Move items to active learning or drop them.
