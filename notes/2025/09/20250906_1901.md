# Notes on REST vs GraphQL — what I've concluded after using both

Spent several years building REST APIs and the last 18 months working with a GraphQL API in production. Some honest conclusions.

**Where GraphQL genuinely wins**

When clients need flexibility in the data they fetch, GraphQL's query language is elegant. Mobile clients in particular often need different data shapes than web clients — with REST, you either build client-specific endpoints or you return more data than needed. GraphQL handles this cleanly.

Introspection and the schema are excellent. A typed, self-documenting API that tools can query is a genuine advantage. GraphiQL and similar tools let frontend developers explore the API without asking backend developers.

**Where REST is still better**

HTTP semantics map cleanly to REST. Caching is harder with GraphQL because queries go to a single endpoint via POST. CDN caching, which is trivial for REST, requires workarounds (persisted queries, GET-based query parameters) for GraphQL.

File uploads in GraphQL are awkward. Error handling is inconsistent — a GraphQL response with status 200 can contain errors, which confuses middleware and monitoring.

REST is simpler to reason about for simple cases. If your API is mostly CRUD on well-defined resources, GraphQL's complexity isn't buying you much.

**What I actually do now**

REST for new projects unless there's a specific requirement that GraphQL addresses better (complex, multi-level data requirements, federation across multiple services).
