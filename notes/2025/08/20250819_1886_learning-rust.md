# Learning Rust — first real steps

Third attempt at learning Rust. The first two attempts I tried to read the book linearly and stalled around chapter 10. This time I'm building something first and reading the book when I hit walls.

**What I'm building**

A small CLI tool that watches a directory and reports file changes with timestamps. Small enough to finish but touches the file system, threading, and the borrow checker in non-trivial ways.

**The ownership model — what finally clicked**

The borrow checker enforces at compile time that: (1) you can have multiple immutable references or one mutable reference, but not both. (2) references can't outlive the value they refer to.

The second rule (lifetimes) is what confuses people initially. Once you understand that the compiler is preventing you from creating a reference to memory that might have been freed, it becomes less mysterious. Rust is making explicit the rules that C/C++ developers have to track manually.

**The error messages**

The Rust compiler error messages are genuinely the best I've seen in any language. When the borrow checker rejects something, it usually explains why and suggests a fix. This makes the learning curve feel less arbitrary than it otherwise would.

**Where I've gotten stuck**

`async` in Rust is more complex than in Python or JavaScript. The Tokio runtime, `Pin`, `Future` trait — there's more ceremony. I'm avoiding async for now and using standard threads for this project.

**Current state**

File watching works. The output is formatted correctly. Working on the filtering logic (ignore certain file patterns). Maybe 60% done.
